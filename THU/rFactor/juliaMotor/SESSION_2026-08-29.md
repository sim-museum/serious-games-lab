# Julia Racer — session status, 2026-08-29

## E91 — "Tesla brakes": **the PO is right, and it is measured**

`coast_compare.jl` compares TOTAL off-throttle deceleration between the sim and the iRacing reference at matched speed and gear. **No decomposition** — the PO's complaint is about total deceleration, which is directly observable on both sides, so none of the fitting problems apply.

**Median sim/ref ratio 1.67× across 8 matched bands, all 8 above 1.0** (1.06–2.48). The complaint is confirmed. An earlier session's explanation that the PO was driving too slowly to need brakes is **positively refuted** and must not be repeated.

⚠️ **This is an acceptance criterion, not a fix.** It says the total is too high, not which term causes it. Three sprints established this telemetry cannot apportion it: a road-course coast segment is never straight, flat and un-steered long enough. `ENGBRAKE = 0.012` stays — replacing it with an equally unsourced number would satisfy "physics from the .ibt" in letter and break it in substance.

**PO action that settles it (~2 min):** one straight-line coast-down, ~200 → 60 km/h, full lift, no brake, no steering — run **twice**, in gear and clutch-in. The difference between those curves IS engine braking, with nothing to fit. It must explain a **1.67×** excess.

## Method note — five predictions, four already wrong

Per-billboard cost (**20×** high), HAT-cell density (**10⁴** wrong), `.dat` pack size (file I/O is 0.2 %), and "super-linear" itself (possibly a wrong-denominator artefact). **Every one was a per-unit figure obtained by DIVIDING a phase time by a count, then attributing the quotient to the most visible thing in the phase.** Each was cheaper to refute than to defend, because the number was written down first. Counting is not more work than arguing.
